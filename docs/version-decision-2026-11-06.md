# 版本号决策一页纸（2026-11-06 收口用）

_构件轮备 · 待灵泽拍板 · 一分钟读完_

## 现状

`package.json` = **`0.1.0-peripheral`**（外围可用版，11-01 定）。此后三天新增：评测四维出数、混合裁决、跨进程桥、zcode 宿主适配器、DSH 端到端闭环（一次）、外部审库响应。

## 三个候选

| 方案 | 版本号 | 逻辑 | 代价 |
|---|---|---|---|
| A 维持 | `0.1.0-peripheral` | 还没「入库发布」，peripheral 语义仍准确 | 周五的提交全挤在一个旧号里，作品集叙事少一个版本点 |
| B 进一位（推荐） | `0.2.0-peripheral` | 评测体系+跨进程桥+宿主适配器都是**能力级**新增；「peripheral」后缀继续诚实标注「无活 Session」 | 改一行 package.json + CHANGELOG 挂号 |
| C 抹平 | `0.2.0` | 去后缀，宣称通用可用 | 不诚实——B2 活 Session 还没交付，评委会问 |

## 推荐

**B**。理由：`-peripheral` 后缀是诚实边界（README 首屏就在讲）；`0.1→0.2` 的跨度真实反映了这三天（评测从 0 到五维全数、桥从无到闭环）。等活 Session 交付再抹后缀升 `0.3.0`，那时「到岗」才是完整的通用工具。

## 配套动作（拍板后构件轮执行，10 分钟）
