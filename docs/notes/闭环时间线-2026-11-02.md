## 闭环是怎么接上的

```text
pnpm dispatch "…"
  → 路由 {target, urgency, cards}（Flash + 关键词规则）
  → 接单成功：追加 $DAOGANG_HOME/triggers.jsonl
  → DSH inbox source：轮询 tail → Trigger 进 feed
  → DSH orchestrator：Policy 准入 → Ticket / Assignment
  → worker Session（一票一会话）
  → 开 PR + 回源对话
```

到岗这边只负责「一句话变成一条合法 Trigger」。过桥之后，评估、建票、起 worker 用的是 DSH 自己的 orchestrator。所以这条闭环的关键不是桥本身，而是桥加 Policy：两条试跑任务都被 `not_a_member` 挡下，第三条把 actor 和 Policy 名单对齐后才 accept。跨进程只解决了「送得到」，Policy 才决定「接不接」。
