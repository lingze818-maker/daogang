## 附带发现

1. **重投语义**：feeder 首启 seen 为空时会把文件里全部历史行当新行重投（11-06/11-05 旧 trigger 复活）。下游按 trigger id 幂等（disposition ON CONFLICT 更新），无重复开票，但旧任务会被重新评估甚至重开票——**正式部署必须配 stateFile（`DAOGANG_FEEDER_STATE`）续读**，本刀已支持，CLI 默认即开。
2. **chat 腿也会渡桥**：dispatch 的 chat 腿（target=main）同样经 feeder 进库开 main 票——读侧不挑腿，与写侧语义一致。
3. **API 同源约定**：管理 API 要求 `x-orchestrator-request: 1` 且无 Origin（上游 http.ts `sameOrigin`），feeder 已带。
4. **上游 TS 参数属性**：`store.ts` 构造器用 parameter property，Node strip-only 拒载——feeder CLI 要求 `--experimental-transform-types` 启动（`scripts/check-effects.mjs` 同一约束）。
