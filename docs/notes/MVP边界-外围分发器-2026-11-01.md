## 可用版先做成什么

**外围服务 + inbox Source**，不先 fork 改 Engine 内核。

1. **分发器进程（自建）**：吃用户一句话 → 输出 `{target, urgency, cards}`（Flash + 关键词兜底）→ 写成合法 Trigger / 审计行。
2. **inbox Source 插件（贴底座）**：`SourceContext.receive` 灌入；Policy 尽量 **explicit 直通**，避开 inferred 主 Session 研判拖时长。
3. **「会话起」**：仍走底座 Assignment → `DshExecutor.start` / Effects `launch`·`delivery`；一票一 `worker-<ticketId>` Session（**不是**预案初稿里的 3 个长驻角色进程）。
4. **看板**：审计/交接双写到到岗自建表（SQLite/JSONL）；可参考底座 Store 事件，不绑死其 schema。打断备注 ≤200 字。
5. **招领安全网**：目标不可用/超时 → 条目落板待领（自建）；底座无完整 urgency 抢占，抢占语义 MVP 可降级为「只打断 idle / 或 addInput 唤醒」。

## 刻意不做（可用版）

- 不改 `Engine` 私有规则、不依赖未导出内部类
- 不假装有 bridge；Panel 只当运维面
- 不对影/zcode/Codex 适配器（接口草图可另开短文，实现放阶段 E）。优先级：对影 > zcode > Codex
- 不上游开 Issue（仓 `has_issues: false`）
