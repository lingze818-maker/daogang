# D1 · mini-bench：路由准确率

100 条虚构混合输入（50% 纯任务 / 30% mixed / 20% 路由陷阱），对关键词兜底路由（`routeByRules`）打分。无密钥、无网络，可复跑：

```bash
node --experimental-strip-types bench/run-bench.mjs
```

产物：`results-keywords.json`（汇总+错例）、`results-keywords-all.jsonl`（逐条）。

## 构成

| 组 | n | 特点 |
|---|---|---|
| task | 50 | 明确派单（含 docs/fix/实现类角色与 0/1/2 三档 urgency） |
| mixed | 30 | 闲聊+任务同句，期望双投 |
| trap | 20 | 12 条「名词误触发」（bug/文档/readme 是话题不是派单）+ 8 条「隐式指代」（"那个部署的事""订阅按钮还是坏的"，无任务词但人在派活） |

标签以「人的真实意图」为准，不迁就规则——这是 D2 对照（Flash 路由跑同一数据集）的公平基线。

## 首跑（2026-11-02，关键词兜底）

| 组 | target 准确率 | urgency 准确率 |
|---|---|---|
| task | 0.88 | 1.00 |
| mixed | 0.73 | 1.00 |
| **trap** | **0.15** | 1.00 |
| **总体** | **0.69** | **1.00** |

## 三类盲区（全部错例可复查）

1. **名词误触发**（trap 主要错因）：吐槽「这个 bug 太离谱」、夸奖「文档写得真好」、提问「安装教程在哪」都被名词命中开成工单。
2. **闲聊词表覆盖窄**（mixed 主要错因）：「早呀/哈喽/晚上好/好累/麻烦」都不在 CHAT 表，问候+任务被降级成纯任务，主窗腿丢失。
3. **祈使句无呼语**（task 6 错共性）：「把版本号更新到 0.2」「紧急：把 key 清掉」——没有「帮我/麻烦」前缀的祈使句 TASK 不命中，被推给主窗。

## 结论与下一步

关键词兜底在「标准表述」下够用（task 0.88 / urgency 1.00），在「人话的自然波动」（同义问候、指代续话、名词吐槽）下崩到 0.15——**这组数字就是 Flash 路由的存在理由**。D2：额度恢复后设 `DEEPSEEK_API_KEY` 跑 Flash 路由对同一数据集，出对照表；若 Flash 在 trap 组显著高于 0.15，"小模型路由+关键词兜底"的双层设计就有数据支撑。

D3 拟人五维的其余四维（首响延时/打断恢复/上下文重建/节奏分布）不依赖本 bench，走 dispatch 实测路径。

# D3 · 打断恢复正确率（外围路径）

`node --experimental-strip-types bench/run-d3.mjs`，无密钥无网络。12 用例三层：

| 层 | 用例 | 覆盖 |
|---|---|---|
| 纯函数（assignTask） | u01–u10 | 空闲接单 / 同级不打断 / 低不打高 / 高打断低 / 打断后 FIFO / 队中多单打断排尾 / 交接备注 ≤200（含超长摘要 clamp）/ 被打断工单五字段无损 |
| 落盘恢复（WorkerLane） | r01 | 打断后状态 save→load 全等——"走神能回来"的前提 |
| 端到端（dispatchLine） | e01 | 普通→急 mixed→不急 三连：打断者 running、被打断行翻 queued 且看板备注含「打断」、不急单排队 |

## 结果（2026-11-02）

**12/12 通过（pass_rate 1.000）**，exit 0。逐用例明细见 `results-d3.json`（含失败原文字段，本轮无失败）。

## 边界说明

- 本套量的是**打断语义正确性**（谁被打断、去哪、备注什么、信息丢没丢），不含"恢复后继续干"——那需要活 worker Session（B2 后续），届时在此套追加"打断→恢复→续作"用例。
- 拟人五维计分：本套对应「接得住打断」维，当前满分基于外围实现；底座真接后需重跑。
