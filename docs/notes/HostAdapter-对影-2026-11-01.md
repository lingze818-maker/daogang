# HostAdapter · 对影优先

_到岗 · 阶段 E1 接口骨架 · 2026-11-01_
_给鎏虹。公开说明，没有私有样本，也没有对影接口草案。_

## 落在哪

代码在 `packages/host-adapter`。五个方法：

| 方法 | 本地 CLI（`LocalCliHost`） | 对影（`DuiyingHost`） |
| --- | --- | --- |
| `sendMessage` | 主窗走现有的「主窗先接住」；`worker-<ticketId>` 写入本地 `executor.json` 的 delivery | 拒绝执行 |
| `openSession` | `main`，或 `worker-<ticketId>`。只起名字，不启动 DSH | 拒绝执行 |
| `interrupt` | 与分发器相同：只有更高优先级才放下当前工单，交接备注不超过 200 字 | 拒绝执行 |
| `readContext` | 读本地 `worker.json` 的摘要和 `board.jsonl` 里已有的交接 | 拒绝执行 |
| `auth` | `anonymous`。不读密钥 | `unconfigured`。不读密钥 |

`createHost()` 默认是 `local-cli`。`pnpm dispatch` 不经过这个包。执行口默认仍是 `LocalExecutor`。

## 假设

下面是到岗这边的工作假设，**还没有和鎏虹核对**：

1. 对影是第一宿主。zcode、Codex 排在后面，这一页不写它们。
2. 对影负责窗口里的一句还在不在；到岗继续做路由、紧急度和招领。换宿主不改分发规则。
3. 对齐之前，对影适配器不发请求。半真半假的客户端比空桩更难拆。
4. 产品层可以有多个角色名。实现层仍是一票一个 `worker-<ticketId>`，不是三个常驻进程。对影若已有会话名，以对影为准，到岗再映射。

5. 鉴权用对影里用户已经登录的状态，还是到岗单独持有一份凭证？凭证放在哪、谁轮换？这个仓库不收凭证样例。
6. 对齐后的第一条可演示路径是什么？阶段 E7 需要至少一条 happy path，现在还没有。
