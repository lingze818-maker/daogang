## 现象

服务重启（同 patch、同 env）后，inbox source 持续 receive trigger：health 是 ready，detail 更新到最新 id，stats.received 增长，orchestrator 的 judged 同步增长。但 **threads=0、decisions=0、accepted 卡在旧值**：trigger 被 receive + judge，却不建立 thread / candidate，永远到不了 accept。

前一晚（11-03 00:10 前后）同一份代码、同一 patch 可以走通：policy PUT 填好名单后 accepted=1、running=1，worker 开出 PR #26。问题出现在同码重启之后，不是代码变更。

## 已排除

- Policy 名单：重启后持久化完好（revision 1，`github: lingze818-maker` / `inbox: cli`），trigger actor=`cli` 对齐。

## 嫌疑

- 重启后 orchestrator 内部状态差异（thread 建立 / `SourceContext.receive` → 评估管线之间）。
- 或 assessment 对「可否 accept」的某个前置条件在重启后不满足，且没有可见报错。decisions API 返回空列表，也说明评估产出没有落库。
